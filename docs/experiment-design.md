# Планирование вычислительных экспериментов

**Experiment** — верхний уровень воспроизводимого сравнения нескольких сценариев и повторных запусков.

```text
Experiment
 ├── Baseline Scenario
 ├── Project Scenario
 ├── Alternative Scenarios
 ├── random seeds
 ├── replications
 ├── KPIs
 └── statistical comparison
```

## Отличие

- **Scenario** — фиксированное состояние и набор изменений.
- **SimulationRun** — один фактический запуск сценария с конкретными входами и seed.
- **Experiment** — протокол сравнения множества сценариев и запусков.

## Повторяемость

Каждый эксперимент фиксирует:

- цель;
- сценарии;
- версии данных и моделей;
- параметры;
- период;
- число повторов;
- seed policy;
- common random numbers, если применимо;
- набор KPI;
- статистический метод сравнения;
- критерий практической значимости.

## Повторы

При наличии случайности один запуск не считается достаточным для сравнения сценариев. Каждый запуск сохраняет seed, сценарий, входные данные, параметры, версию модели и результат.

## Парные эксперименты

Baseline и проектный сценарий по возможности запускаются на одинаковых случайных последовательностях, чтобы уменьшить дисперсию оценки разницы. Это не устраняет систематическую ошибку модели.

## Статистика

Для KPI хранятся:

- среднее;
- медиана;
- стандартное отклонение;
- квантили;
- доверительный интервал или другой заранее выбранный показатель неопределённости;
- абсолютное и относительное изменение;
- практическая значимость.

Статистическая значимость сама по себе не означает транспортной или проектной значимости.

## MVP

Минимальный эксперимент Pulse: один небольшой коридор, baseline, один проектный вариант, несколько репликаций, согласованные seeds, 10 ключевых KPI и независимая проверка части KPI.
