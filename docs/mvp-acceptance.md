# Критерии приёмки математического MVP

## Область

Один небольшой коридор: 10–20 км; дорожная и пешеходная сеть; один автобусный маршрут; 15–30 остановок; OD по зонам; 10–20 автобусов; фиксированное расписание; фактические отправления; вместимость; посадка и высадка; отказ в посадке; время движения; стоянка; задержка; сбивание интервалов; пассажирское ожидание; KPI; связь с SUMO для дорожной задержки.

## Сквозная цепочка

OD → Mode Choice → Route Choice → Transit Assignment → Capacity → Dwell → Delay → Waiting → Passenger Time → KPI.

Каждый этап должен иметь математический контракт.

## Обязательные доказательства

1. **Воспроизводимость.** Одинаковые версии входов, параметров и seed дают идентичный результат там, где модель заявлена детерминированной.
2. **Сходимость.** Итеративные расчёты имеют критерий, норму, допуск, максимум итераций, статус и поведение при отсутствии сходимости.
3. **Калибровка.** Параметры настроены на calibration dataset.
4. **Независимая проверка.** Validation dataset не используется для настройки.
5. **Эксперимент.** Baseline и проект сравниваются через несколько репликаций при наличии стохастики.
6. **KPI.** Для каждого KPI известны определение, формула, единица, период, совокупность, агрегация и неопределённость.
7. **Физическая выполнимость.** Расписание, вместимость и эксплуатационные ограничения не нарушаются без явной маркировки сценария как невыполнимого.

## Минимальный набор KPI

1. общее пассажирское время;
2. ожидание;
3. время в пути;
4. время пересадки;
5. P90 времени поездки;
6. отказ в посадке;
7. максимальная загрузка;
8. CV интервалов;
9. задержка автомобилей;
10. доступность за 30/45 минут.

## Критерий готовности

MVP не считается доказанным только по факту успешного запуска. Нужны одновременно корректность математических контрактов, воспроизводимость, калибровка, независимая валидация, устойчивость результатов по репликациям, физическая выполнимость и документированные ограничения применимости.
