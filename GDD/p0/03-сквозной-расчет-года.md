# P0.3 — Сквозной расчёт игрового года

## Канонический конвейер

```
STATE SNAPSHOT
  ↓
VALIDATE NETWORK
  ↓
SERVICE / SCHEDULE
  ↓
DEMAND GENERATION
  ↓
TRIP DISTRIBUTION
  ↓
ROUTE CHOICE (rRAPTOR)
  ↓
MODE CHOICE
  ↓
CAPACITY / CROWDING
  ↓
AGGREGATION
  ↓
ECONOMICS
  ↓
MODEL VALIDATION
  ↓
YEAR REPORT
```

## Правила
Расчёт начинается со снимка состояния. Изменения редактора после создания снимка не влияют на текущий расчёт.

Каждый этап имеет:
- версию алгоритма;
- входной набор;
- выходной набор;
- контрольную сумму;
- длительность;
- статус.

## Инвалидация
| Изменение | Пересчитать |
|---|---|
| остановка/геометрия маршрута | service → demand → routing → mode → economics |
| интервал/расписание | service → routing → mode → economics |
| тариф | mode → economics |
| население/рабочие места | demand → distribution → routing → mode → economics |
| только UI | ничего |
| название объекта | ничего |

## Детерминированность
Одинаковые:
- пакет города;
- состояние сети;
- seed;
- версия модели;
- версия рантайма

должны давать одинаковый отчёт с точностью, определённой численным контрактом модели.

Параллельные вычисления не должны менять логический результат из-за порядка суммирования. Для чувствительных агрегатов используется детерминированный порядок редукции.

## Ошибка
При ошибке этапа:
- текущий результат помечается failed;
- неполный годовой отчёт не публикуется;
- предыдущий успешный отчёт остаётся доступным;
- сохраняется диагностический журнал.

## Кэш
Ключ кэша включает `package_version + state_hash + model_version + stage_version + relevant_inputs_hash`.

## Отмена
Отмена не заменяет предыдущий успешный результат и не оставляет частично опубликованный новый результат.

## Годовой отчёт
Отчёт является атомарным объектом и содержит результаты спроса, маршрутизации, режима, загрузки, экономики, качества модели и метаданные расчёта.
