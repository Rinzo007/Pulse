# P0.2 — Контракт пакета города

## Назначение
Пакет города — версионированный, воспроизводимый вход симулятора. Игровой рантайм не должен угадывать отсутствующие обязательные данные.

## Обязательные слои
- `manifest.json`
- граница города и зоны спроса
- население
- рабочие места
- точки/матрица спроса
- дорожный граф
- остановки и платформы
- маршруты
- расписания/рейсы
- доходы/VOT
- `cost-model.json`
- `reference_network.json`
- векторные тайлы

## manifest.json
```json
{
  "schema_version": "1.0",
  "city_uid": "provider:code",
  "name": "...",
  "country": "...",
  "timezone": "...",
  "currency": "...",
  "coordinate_reference_system": "...",
  "data_date": "YYYY-MM-DD",
  "build_date": "YYYY-MM-DD",
  "sources": [],
  "files": [],
  "license": {}
}
```

## Происхождение
Каждый файл обязан иметь источник, дату актуальности, дату загрузки, лицензию, преобразования и контрольную сумму.

## Семантика значений
- отсутствует = неизвестно;
- 0 = достоверное отсутствие;
- observed = наблюдение;
- estimated = оценка;
- modeled = результат модели.

Эти состояния нельзя смешивать.

## Идентификаторы
Идентификаторы внутри пакета стабильны. При обновлении исходных данных новые объекты получают новые IDs; переименование не должно создавать дубликат.

## Проверки сборщика
1. CRS и временная зона определены.
2. Все обязательные файлы присутствуют.
3. Контрольные суммы совпадают.
4. Ссылки между объектами разрешаются.
5. Нет дубликатов обязательных IDs.
6. Геометрии валидны.
7. Единицы и валюты объявлены.
8. Диапазоны значений проходят sanity-check.
9. reference_network воспроизводим.
10. Лицензии позволяют заявленный способ распространения.

Пакет с ошибкой не загружается в режим игры.

## Версионирование
Изменение схемы повышает `schema_version`. Изменение исходных данных без изменения схемы создаёт новую `package_version`.

## Обновление
Сохранение содержит `city_uid`, `package_version` и `model_version`. Старый пакет не заменяется автоматически новым.
