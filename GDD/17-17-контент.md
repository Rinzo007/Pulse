# 17. Контент

## 17.1 Формат пакета города

| Файл | Обязателен | Содержание |
|---|---|---|
| `demand_data.json(.gz)` | **да** | Точки спроса и группы поездок (§7.3) |
| `buildings-stats.bin(.gz)` | **да** | Население и рабочие места **по зданиям** (§7.2.5); агрегация в зоны — на лету |
| `buildings-index.bin(.gz)` | **да** | Бинарный индекс зданий с глубинами фундаментов |
| `roads.geojson(.gz)` | **да** | Дорожная сеть для коллизий и уличного движения |
| `runways_taxiways.geojson` | нет | Аэродромы |
| `ocean_depth_index` | нет | Глубины воды |
| `building_tags.json(.gz)` | нет | OSM-теги по id |
| `income.json` | **да** | Распределение доходов (mean/sd/min/max + год + валюта) для VOT (§9.5) |
| `cost-model.json` | **да** | Себестоимости `S_ijt` по классам и типам ТС + `K_А`, `I_ПЦ`, `R` (§10.4) |
| Тайлы | **да** | Векторные тайлы зданий/дорог/воды |
| `reference_network.json` | **да** | Эталонная реальная сеть + опубликованный пассажиропоток (§12) |

**Индекс зданий — бинарный, не JSON.** Решение из `[СБ]`, и оно важное: индекс Лос-Анджелеса — **≈1 ГБ как JSON против ≈50 МБ как типизированные массивы**. Индексация по равномерной сетке ~100 м для быстрого поиска коллизий.

**Идентификация города:** `uid = <mod id>:<code>`; внутренний код — `code` разработчика. Гарантия из `[СБ]`, которую мы сохраняем: **код может совпасть с чужим, оба города останутся играбельными, ни один не вытесняется**; сохранение привязано к правильному городу через uid.

**Обоснование Казани как первой неевропейской площадки `[Я22]`:** авторы строили модели **всех городов РФ с населением >250 тыс.** начиная с 2018 года, в том числе Перми, Самары, Екатеринбурга, Казани, Саратова, Ульяновска, Ижевска и др. Это означает, что для Казани **существует проверенная отраслевая модель с откалиброванными функциями предпочтения и затрат** — то есть наш калибровочный гейт (§12.4) проходим по данным, а не по надежде. См. §12.5 с эталонными значениями по трём городам.

**Позже:** Варшава, Стамбул, Лос-Анджелес `[П]`; Вашингтон `[СБ]`.

**Гейт готовности города** (город не выходит, пока…):
- расхождение с реальным пассажиропотоком ≤ 15% (§12.3);
- ≥ 300 точек спроса;
- покрытие ≥ 90% населения площадью застройки;
- тайлы до зума 15 без провалов;
- 10 эталонных сценариев воспроизведены без ошибок.

## 17.3 Нарративный слой

Механика газет и соцсетей из `[СБ]`:

| Элемент | Поля | Условия появления |
|---|---|---|
| Газетная статья | `headline`, `content`, `category` (milestone/news/opinion), `tone` (celebratory/professional/critical), `weight` | `minStations`, `minRoutes`, `minPassengers`, `minMoney` |
| Пост в соцсети | `text`, `tone` (excited/angry/neutral) | те же |
| Переменные | `{{STATIONS}}`, `{{ROUTES}}`, `{{CITY}}`, `{{PASSENGERS}}`, `{{RIDERSHIP}}` | — |

**Дизайн-правила из `[СБ]`, которые мы принимаем:** писать город-специфично (местные ориентиры, названия операторов, культурные детали); чередовать тона; ставить реалистичные пороги; взвешивать 8–10 для вех и 3–5 для «флёвр»-контента.

**Наша доработка `[Р]`:** газеты выходят **в полночь, по итогам закрытого дня**, а не в момент события. Это исправление реального бага из `[СБ]` (v1.4.17): газеты выходили ночью, когда поезда стояли и никто не ехал, поэтому бурную сеть описывали как заброшенную.

**Роль нарратива у нас:** не украшение, а **канал объяснения**. Газета не «молодец, вы построили сеть», а сообщает о проблеме: «Перегон K в 07:30 переполнен: 112% от вместимости. Интервал 8 минут не спасает — проблема в длине платформы». Это связывает нарратив с моделью.
