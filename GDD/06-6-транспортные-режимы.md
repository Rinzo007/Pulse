## 6.3 Общие пути (shared track) и параллельные пути

Модель из `[П]`:

- линия может идти **по пути другой видимой линии того же вида** — бесплатно, но делит пропускную способность;
- **параллельный путь** с собственным лимитом (20 м сбоку, те же уровни);
- **стык без станции** (junction) — присоединение между двумя станциями;
- **общая платформа**: новая станция на общем пути обслуживает все линии на нём;
- лимиты считаются по **всем** линиям на секции, включая скрытые, кроме припаркованных `[П]`.

**Что добавляем:** явный индикатор «занято X из Y поездов в час» на каждом секторе **при перетаскивании takt** — до того, как игрок отпустит ползунок. `[П]` останавливает ползунок и объясняет постфактум; мы показываем предел превентивно.

## 6.5 Размер парка — формула и пороги эффективности

Это закрывает белое пятно A1 (§23): формула «сколько единиц техники нужно линии» и «какой вид выбрать при данном потоке».

### 6.5.1 Цепочка расчёта `[МР21]`

Условный маршрут из `[МР21]` (длина 10 км, оборотный рейс 20 км, скорость 18 км/ч):

```
поток_в_сечении_пик → частота = поток / вместимость(4 чел/м²)
интервал = 60 / частота, с запасом 20 с на опоздание, округление вниз до 0.5 мин
интервал_пик ≤ 8 мин (качество обслуживания — жёсткий порог)
время_оборота = (2 × длина / скорость) × (1 + 0.10) + зарядка (э-бус 10 мин)
выпуск = время_оборота / интервал
парк = выпуск / КТГ        (КТГ: автобус 0.80, ГЭТ 0.90)
рейсы_в_сутки по типовому профилю (14.5 ч при 1 рейсе/ч)
пробег_год = длина_оборота × рейсы / 0.9 × 350
часы_водителя_год = время_оборота × рейсы / 0.9 × 350
```

**Проектная формула `[Р]`** (наш аналог, с откатом к реальной линии):

```
fleet_needed = ceil( (2 × (Σ ride + Σ dwell + turnaround) / headway_peak) / K_в )
```

где `K_в` — коэффициент выпуска: **автобус 0.85, ГЭТ 0.9** `[НМ25]`; `Σ dwell` из §9.7 (stopTime + extraDwell); `turnaround` из данных типа поезда `[СБ]` (120 с). Проверка на условном маршруте: 73.3/8 = 9.16 → ceil = 10 выпуск → 10/0.85 ≈ 12 парк автобуса СК — совпадает с `[МР21]`.

### 6.5.2 Пороги эффективности по потоку `[МР21]`

Ключевые границы (условный маршрут, пиковый поток в сечении, пасс/ч):

| Порог | Что происходит | Стоимость |
|---|---|---|
| **<130** | Автобусы МК оправданы только при редких колебаниях | — |
| **130** | Автобус СК становится экономичнее МК | — |
| **330** | Лучший — **троллейбус**; автобус СК — 2-е место | электробус дороже на 31 % |
| **380** | Дешевле автобуса СК — **троллейбус с увеличенным автономным ходом** | электробус дороже на 31 % |
| **650** | Минимум затрат у **Тб ОБК** | электробус дороже на 38 % |
| **1110** | Выгоднее всего **трамвай** | Тб дороже на 5–8 %, ТУАХ на 16–19 %, автобус на 20 %, электробус на 51 % |
| **1830** | Лидер **трамвай 3×БК** | на 24–26 % экономичнее Тб, на 43 % — автобуса, на 80 % — электробуса |

Дополнительные факты `[МР21]`: автобус БК проигрывает троллейбусу при **любом** потоке на 11–12 % (без учёта первоначальных вложений); автобус свыше 1500 пасс/ч дороже в 1.5–5 раз; автобусы МК «взлетают ракетой» (Газели в 2 раза дороже ОБК-автобуса, в 4 — Тб, в 5 — трамвая).

**Вместимости при 4 чел/м² `[МР21]`:** автобус МК 18–22, СК 43, БК 68, ОБК 93, эл.бус 72–73, Тб БК 73, Тб ОБК 98, Тм-МК 95, Тм-СК 111, Тм-БК 162, Тм-ОБК 226, Тм 2хБК 190, Тм 3хБК 285.

**Проектное применение `[Р]`:** это готовая таблица «совета по апгрейду». Когда поток линии пересекает порог, advice box (§14.4) выдаёт новый тип совета: **«поток N пасс/ч — пришло время троллейбуса/трамвая»**. Это даёт игроку правильную лестницу видов: автобус → троллейбус → трамвай → метро, с реальными, а не выдуманными границами. Лестница из `[П]` (автобус 90 → трамвай 260 → метро 800) и `[МР21]` (автобус 18–93 → трамвай 95–285) согласованы по порядку — мы берём лестницу `[МР21]` как экономическую (она уже учитывает зарплату, топливо, ремонт и инфраструктуру).
